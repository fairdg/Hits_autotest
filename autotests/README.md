# Примеры по написанию задач для автотестов

Здесь имеется 2 папки. `examples` содержит 2 примера готовых задач. `tests-runner` содержит файлы для сборки docker образа, чтобы протестировать свои задачи

## Формат задачи

При написании задач очень важно придерживаться названий файлов и структуры каталогов, которые соответствуют примерам.


Каждая задача состоит из:

1. `solution.py` - решение задачи. Если прогнать его через tests-runner, можно получить такие результаты для различных тест-кейсов, которые вы закладывали при создании задачи.
2. `template.py` - шаблон, содержащий настройки selenium драйвера и имена тестов. Этот шаблон будет передан студенту, поэтому он не должен содержать самого решения или других "спойлеров". Туда можно добавить какие-нибудь пояснения к тестам. Имена тестов должны соответствовать тем, которые в `solution.py` указаны.
3. `task.md` - описание задачи. markdown формат. относительно свободно в плане того, что там напишите. Единственное строгое требование - __укажите название задачи первой строчкой в этом файле__. Можно с "#" или без него.
4. `reference/index.html` - вариант сайта без ошибок. Должен успешно проходить все тесты solution.py
5. `testcases` - папка с тестами. Должна содержать в себе каталоги с числами в названиях. Каждый каталог - отдельный тесткейс. Номер в названии каталога - порядок тесткейса.
6. `testcases/${N}/index.html` - конкретный сайт с ошибкой, представляющий тест.

Важные детали:

- В качестве основных инструментов для тестирования используются pytest и selenium.
- Каждая папка, содержащая в себе сайт (`reference/` или `testcases/.../`) должны в своем корне иметь `index.html`
- Если есть необходимость встроить внешний ресурс в `index.html` (картинку, скрипт), нужно использовать относительные ссылки, т.к. полная url на момент написания тестов вам не известна.
- Каждый тест должен быть независим друг от друга. Из `index.html` одного теста не нужно ссылаться на ресурсы или `index.html` другого теста.
- При необходимость сымитировать роутинг, добавляйте подкаталоги внутрь тесткейсов. Например, если нужно, чтобы на сайте помимо `/` были доступны `/registration` и `/login`, структура каталогов будет выглядеть так:

```
testcases/
    1/
        index.html
        registration/
            index.html
        login/
            index.html
```

- Проверить, как работает ваш сайт, можно с помощью

```bash
python -m http.server -d {ПУТЬ_ДО_ВАШЕЙ_ЗАДАЧИ}/testcases/1 8080
```


## test-runner

Образ для теста своих задач. При его запуске нужно передать папку с задачей. Лежащие в ней `testcases` и `solution.py` будут протестированы.

### Сборка образа
Находясь внутри `test-runner`, выполнить

```bash
docker build -t auto-tests-runner .
```
после выполнения команды в системе появится образ с тэгом `auto-tests-runner`


### Запуск тестов

Чтобы прогнать написанные для задачи тесткейсы против `solution.py`, нужно выполнить следующую команду

```bash
docker run --rm -v ./example/tabletop-catalog:/app --shm-size=2G auto-tests-runner
```


- `--rm` - временный контейнер. удалится сразу же после завершения.
- `-v ./example/tabletop-catalog:/app` - таким образом, ваша задача пробрасывается в контейнер. замените `./example/tabletop-catalog` на путь до вашей задачи. для успешного тестирования структура каталогов и названия файлов в папке с вашей задачей должны соответствовать требованиям из [формат задачи](#формат-задачи)
- `--shm-size=2G` selenium запускает внутри контейнера браузер, без этого параметра браузер, скорее всего, крашнется.

### Результаты выполнения

Если тестирование пройдет успешно, то в папку с задачей добавиться директория `results`. Она будет содержать файлы вроде `results_1.json` и `results_1.xml`. Xml файлы содержут подробные результаты тестирования, json краткие в фомарте `имя теста` - `результат`. `fail` - тест не пройден. `check` - тест пройден. Помимо этого, при выполнении тестов с помощью test-runner образа сам pytest будет генерировать отчет о выполнении.
